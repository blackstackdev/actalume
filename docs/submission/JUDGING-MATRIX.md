# Judging matrix

| Criterion | Actalume case | Proof to show |
| --- | --- | --- |
| WebMCP leverage | Six typed tools expose a complete agent work protocol. The most important design choice is a missing capability: there is no approval tool. | Live `6 tools` state, public source, native execution capture and denial result |
| Execution | The app is persistent, editable, responsive and usable without an agent. WebMCP improves the same human workflow rather than replacing it with a separate chatbot. | Live URL, contract editing, evidence receipt, approval modal, canonical history |
| Potential impact | Solo builders and small teams need accountable agent work, especially when tool calls can alter data or trigger handoffs. | One end-to-end custody chain and clear public-data boundary |
| Creativity and ambition | Actalume treats agent work as an evidence and governance problem, not another automation dashboard. | Contract → Brick → Evidence → Human decision → Canonical history |

## Demo priority

Judges may rely only on the text, images and video. The first 40 seconds must therefore establish the problem and the contract; the middle must prove native WebMCP and the denial boundary; the final third must show the named-human gate and immutable history.
